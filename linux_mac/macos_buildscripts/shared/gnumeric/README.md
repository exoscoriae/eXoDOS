# Portable Gnumeric 1.12.61 for macOS 11+ (universal)

A from-source build system that produces a fully self-contained, drag-anywhere
`gnumeric.app` containing Gnumeric 1.12.61 with GOffice 0.10.61, GTK 3.24 and
the complete dependency stack, as universal (arm64 + x86_64) binaries with a
deployment target of **macOS 11.0**. It works out of the box on a fresh macOS
install: every library is bundled, nothing from Homebrew, MacPorts, or
`/usr/local` is used or required — at build time or at run time. The only
system libraries linked are the ones Apple guarantees on every macOS 11+
system (`/usr/lib`, `/System/Library`).

## Requirements on the build Mac

- Apple Silicon Mac (the scripts auto-detect and also support Intel hosts)
- Xcode Command Line Tools (`xcode-select --install`)
- Rosetta 2, so the x86_64 half can be built and tested natively
  (`softwareupdate --install-rosetta --agree-to-license`)
- Network access for downloading source tarballs (~120 MB)
- ~15 GB free disk space; expect a few hours of build time on first run

## Usage

```sh
./build.sh all          # download → tools → arm64 stack → x86_64 stack → bundle → verify
```

Or step by step:

```sh
./build.sh download     # fetch + checksum all sources
./build.sh tools        # native helper tools (pkg-config, meson, ninja, gettext, intltool)
./build.sh deps arm64   # full library stack for arm64
./build.sh deps x86_64  # full library stack for x86_64 (under Rosetta)
./build.sh bundle       # assemble universal dist/gnumeric.app
./build.sh verify       # audit the result
```

If a package fails, fix the issue and resume: `RESUME_FROM=<pkg> ./build.sh deps <arch>`.
Rebuild a single package with `ONLY=<pkg> ./build.sh deps <arch>`. Completed
packages are stamped in `work/stamps/` and skipped on re-runs.

The result is `dist/gnumeric.app`. Command-line tools are inside it and fully
functional, e.g. `dist/gnumeric.app/Contents/MacOS/ssconvert in.xlsx out.ods`.

## What's enabled

- **ODS** (OpenDocument) import/export — the `openoffice` plugin, plus xlsx,
  xls, csv/tsv, html, dif, sylk, applix, lotus-123, sc, qpro, oleo, xbase,
  mps/lpsolve/glpk and all fn-* function plugins
- Full charting (GOffice plot plugins), **SVG** support via librsvg
  (C implementation 2.40.x — no Rust toolchain needed)
- GTK 3 with native Quartz backend (no X11), CoreText font shaping,
  system fonts via a bundled fontconfig configuration
- Adwaita + hicolor icon themes, GSettings schemas, UI translations
- Printing through the CUPS print backend when detected at build time

Deliberately excluded (with reasons):

- **Python & Perl plugins** — would require bundling an entire language
  runtime (Python) or linking Apple's deprecated system perl, which breaks
  the "works on any fresh macOS 11+ install" guarantee
- **GDA/GNOME-DB** (database plugin), **psiconv**, **paradox** — heavy or
  abandoned dependencies
- **EPS embedding** (needs Ghostscript) and **lasem** equation rendering
- Translated *help* pages (needs itstool; English help is included).
  UI translations ARE included.

## How portability is achieved

1. Everything is compiled with `MACOSX_DEPLOYMENT_TARGET=11.0` and
   `-mmacosx-version-min=11.0` for both architectures; `verify.sh` proves no
   Mach-O slice in the bundle requires anything newer.
2. Gnumeric and GOffice hard-code their data/plugin paths at configure time
   on macOS. Two small, anchored source patches
   (`patches/relocate-*.py`) make those paths overridable via environment
   variables, which the launcher (`Contents/MacOS/gnumeric`) sets relative to
   the bundle location. GTK, GLib, gdk-pixbuf and fontconfig are relocated
   via their standard environment variables.
3. All install names are rewritten to `@rpath/...` with the rpath anchored at
   `@executable_path/../Resources/lib`; every binary is then ad-hoc re-signed
   (required on Apple Silicon).
4. Core image loaders (png/jpeg/gif/bmp/ico/…) are compiled *into*
   gdk-pixbuf, so no fragile loader cache is needed; the SVG loader cache is
   regenerated by the launcher on each start.

## Verification

`./build.sh verify` checks every Mach-O file in the bundle for: both
architectures present, min-OS ≤ 11.0 per slice, no dependencies outside the
bundle/`/usr/lib`/`/System`, no leftover absolute rpaths — and runs a
csv → ods → csv roundtrip through the bundled `ssconvert` under both
architectures.

## Checksums

GNOME-hosted tarballs are verified against GNOME's published `.sha256sum`
files. All other tarballs use trust-on-first-use: the first download records
its SHA-256 in `config/checksums.lock`, and later downloads must match.

## Known limitations

- The app is ad-hoc signed, not notarized: on first launch, right-click →
  Open (or `xattr -dr com.apple.quarantine gnumeric.app` after copying).
- Double-clicking a document in Finder launches Gnumeric but does not open
  the file (GTK3/Quartz lacks Apple Event document handling without
  gtk-mac-integration); use File → Open or drag into the window.
- Menus appear inside the window (GTK style), not in the macOS menu bar.
- GLib's own internal messages stay in English (its locale dir is not
  relocatable); Gnumeric/GTK UI translations work.
- If you redistribute the bundle, remember Gnumeric is GPL: make the sources
  (`work/src/` plus `patches/`) available alongside it.

## Layout

```
build.sh              orchestrator
lib/common.sh         env, manifest (pinned versions/URLs), download, helpers
lib/recipes.sh        host tools + per-package build recipes
lib/bundle.sh         .app assembly, lipo, signing
lib/relocate_tree.py  Mach-O install-name rewriter
patches/              relocation patches applied to gnumeric/goffice sources
resources/            launcher, Info.plist, fonts.conf, settings.ini
work/                 downloads, build trees, per-arch roots (disposable)
dist/gnumeric.app     the product
```
